# L-002D — authenticated Witness append and crash recovery candidate

2026-10-20. **Isolated laboratory accepted; release BLOCKED.** Implementation: `crates/loom-store/src/witness_append.rs`. This is a new candidate ACL/Witness format, separate from the L-001 `UnifiedPolicyJournal`; no existing journal or production policy is migrated.

The Root-verified `VerifiedResourceTrust` chooses the Owner, resource, writer epoch and two Witness keys. Every append signs `LOOM:WITNESS-APPEND:V1\0` followed by the exact manifest commitment, expected generation, previous head, Peer ID, TLS key epoch, membership epoch, read-allow bit and validity interval. All integers use fixed-width big-endian encoding; the record has one exact length, one canonical boolean encoding and an Ed25519 signature. There is no remotely accepted Owner key or unsigned writer callback. An Owner-signed false bit revokes all epochs of that Peer on this resource; this format cannot grant write, connect or administer.

Each log is explicitly created with exclusive file enrollment. Opening a missing/corrupt log never creates a replacement. SQLite uses DELETE journaling, synchronous FULL and bounded busy handling. An IMMEDIATE transaction fully replays every signature and predecessor, compares the requested state, inserts the complete signed record and commits before acknowledging. The full record digest becomes the next policy head; revocations additionally extend a domain-separated accumulator. Sequence gaps, changed manifests, zero epochs, unsigned/corrupt history, stale predecessors and expired new appends fail closed. History replay retains revocations after their issuance envelope expires. A lost acknowledgement can retry the identical committed bytes, even after request expiry, while Root enrollment remains valid.

A different Owner-signed transition for an already recorded predecessor is persisted with the accepted transition as fork evidence. It leaves the selected history unchanged and quarantines all history reads, appends and signed observations, including after reopening. `fork_evidence()` exports and verifies both signatures. There is no automatic winner selection or reset API.

The two Witness logs and local policy log are three separate transactions. **There is no distributed atomic commit.** Partial success produces divergent fresh observations and refuses reads until the exact signed request has been durably applied to every participant. A caller must treat timeout or COMMIT failure as ambiguous and retain the original signed request; creating a replacement can correctly trigger fork quarantine.

`WitnessLog::inspect` holds a SQLite read transaction only around bounded local work. In DELETE mode another connection cannot commit while the chunk is copied. Remote observation/signing callbacks run before that transaction, followed by replay and exact snapshot comparison. This fences participating connections to the same database, not a second restored file or another device's journal.

The explicit `witness-lab` feature exposes commit-boundary observation for process fault injection. The normal append path uses the same implementation with an empty observer. Six real SIGKILL experiments per OS cover grant and revoke at before-insert, after-insert/before-COMMIT and after-COMMIT/before-acknowledgement. The first two recover the prior policy; the last retains the committed policy. Exact retry, partial-quorum refusal and completion are checked through actual TLS file opens.

The lab uses public fixture signers and same-host SQLite files. FULL/fsync and SIGKILL tests do not prove physical power-loss durability, protected key custody or independence. Witness network endpoints, authenticated remote enrollment/rotation, independent rollback floors, operator independence, compulsory production writer participation, Byzantine availability and administrative fork repair remain unimplemented. No `VerifiedProviderEvidence`, production `AdmissionPermit` or ServiceOpen is minted.
